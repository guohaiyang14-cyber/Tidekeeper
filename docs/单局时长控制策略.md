# 单局时长控制策略

> **版本**：v1.2
> **日期**：2026-08-05
> **目的**：为 UI/UX 设计提供单局时长控制的前置输入，确保局均时长稳定在 20 分钟左右（P95 ≤ 25 分钟）
> **适用范围**：MVP 阶段

---

## 一、时长目标与硬约束

### 1.1 核心指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **局均时长** | **约 20 分钟** | 目标均值（与主文档 §4.3 / §11.1 一致） |
| **P95 时长** | **≤ 25 分钟** | 设计验收硬指标（超时优先压昼间 UI，非强制踢出） |
| **强制终止** | **无** | 不因超时踢出对局；「提前收工」由玩家主动 |

### 1.2 时长预算分配（基准局）

| 阶段 | 时长 | 占比 | 说明 |
|------|------|------|------|
| **启程** | 0.5 分钟 | 2.5% | 选角色、难度、种子 |
| **战斗** | **18 分钟** | 90% | 16×45s + 60s + 90s + 90s + 120s |
| **抉择之昼** | **1.5 分钟** | 7.5% | 19 段 × 平均 5 秒（**快速玩家基准**；加权平均约 3 分钟，见 §3.3） |
| **总计** | **20 分钟** | 100% | 基准局（加权约 21 分钟，仍在 P95≤25 内） |

## 二、战斗时长控制策略

### 2.1 夜晚时长设定

| 夜类型 | 时长 | 说明 |
|--------|------|------|
| 常规夜（1-4, 6-9, 11-14, 16-19） | **45 秒** | 固定时长，无论敌人是否清完 |
| 精英夜（5） | **60 秒** | 增加 15 秒应对精英密集 |
| 天灾夜（10, 15） | **90 秒** | Boss 战需要更长反应时间 |
| 天灾夜（20） | **120 秒** | 终局 Boss 多阶段 |

### 2.2 战斗时长硬约束

**原则**：夜晚时长固定，不随战斗情况动态调整。

| 情况 | 处理方式 |
|------|---------|
| 敌人提前清完 | 空窗期（可拾取掉落、移动） |
| 敌人未清完 | 无条件进入白天，敌人消失 |
| 玩家死亡 | 进入挣扎模式或结算 |

## 三、抉择之昼时长控制策略

### 3.1 设计理念

**"无强制倒计时"** 是本作的核心设计理念，尊重玩家决策节奏。

| 设计点 | 说明 |
|--------|------|
| 无硬性倒计时 | 玩家可以无限停留 |
| 可随时跳过 | 提供"立即进入下一夜"按钮 |
| 软提示而非硬约束 | 用 UI 文字引导，不强制操作 |

### 3.2 UI 设计规范

#### 主界面布局

```
┌─────────────────────────────────────────┐
│  [商店]  [重铸]  [事件]  [休息]          │
│                                         │
│  （当前内容区域）                        │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │ 💡 建议用时：约 20 秒           │   │ ← 软提示（淡灰色，不抢眼）
│  └─────────────────────────────────┘   │
│                                         │
│  [ 立即进入下一夜 ]  ← 主按钮，默认焦点  │
└─────────────────────────────────────────┘
```

#### 提示文案与时机

| 时机 | 提示内容 | 样式 |
|------|---------|------|
| 进入抉择之昼时 | "💡 建议用时：约 20 秒" | 淡灰色文字，右下角 |
| 停留超过 40 秒 | "可随时跳过进入下一夜" | Toast 提示，3 秒后消失 |
| 停留超过 90 秒 | 无额外提示（避免催促感） | — |

#### 跳过按钮设计

| 元素 | 规范 |
|------|------|
| 按钮文案 | "立即进入下一夜" 或 "下一夜 →" |
| 默认焦点 | ✅ 焦点默认在此按钮上 |
| 键盘快捷键 | Space / Enter / Esc |
| 视觉权重 | 主按钮样式（高亮、居中） |

### 3.3 行为预估模型

假设玩家群体分为三类：

| 玩家类型 | 占比 | 抉择之昼行为 | 时长预估 |
|---------|------|------------|---------|
| 快速玩家 | 40% | 立即跳过或 <10 秒 | 5 秒 × 19 = 1.5 分钟 |
| 普通玩家 | 45% | 正常决策（商店/升级） | 10~15 秒 × 19 = 3~5 分钟 |
| 慢速玩家 | 15% | 深度思考/多轮重铸 | 20~30 秒 × 19 = 6~10 分钟 |

**预期结果**：
- 局均抉择时长：约 **3 分钟**（加权平均）
- P95 抉择时长：约 **6 分钟**
- 总局时长：18 + 3 = **21 分钟**（符合目标）

## 四、应急预案：实测时长超标的处理

### 4.1 监测指标

| 指标 | 触发阈值 | 说明 |
|------|---------|------|
| 局均时长 | >22 分钟 | 黄色预警 |
| P95 时长 | >25 分钟 | 红色预警 |
| 抉择之昼平均时长 | >15 秒/段 | 黄色预警 |

### 4.2 应急处理方案

#### 方案 A：优化 UI 默认选项

**触发条件**：抉择之昼平均时长 >15 秒/段

| 措施 | 说明 |
|------|------|
| 自动预选最佳选项 | 三选一时，自动高亮权重最高的选项 |
| 商店折扣项置顶 | 折扣物品自动排在首位 |
| 一键购买按钮 | 增加"购买全部推荐项"功能（需额外设计） |

#### 方案 B：缩短战斗时长

**触发条件**：局均战斗时长 >18.5 分钟

| 措施 | 说明 |
|------|------|
| 常规夜 45s → **40s** | 减少 5 秒/夜，总计省 80 秒 |
| 精英夜/天灾夜保持不变 | Boss 战节奏不变 |

#### 方案 C：增加跳过提示强度

**触发条件**：抉择之昼停留时间 >60 秒

| 措施 | 说明 |
|------|------|
| 动画提示 | "下一夜"按钮增加脉冲动画 |
| 声音提示 | 每隔 30 秒轻音提示（可关闭） |

#### 方案 D（极端情况）：引入硬性倒计时

**触发条件**：P95 时长持续 >28 分钟 且 用户反馈正面

| 措施 | 说明 |
|------|------|
| 抉择之昼 90 秒倒计时 | 仅在停留超过 90 秒后启动 |
| 倒计时结束后自动进入下一夜 | 最后 10 秒有倒计时音效 |
| 可手动延长 | 点击"再考虑"延长 30 秒（最多延长 2 次） |

**注意**：此方案需通过用户测试验证，仅在确实造成问题时启用。

## 六、数据埋点需求

### 6.1 必须埋点

| 事件名 | 字段 | 用途 |
|--------|------|------|
| `night_start` | night_id, night_type | 战斗开始时间戳 |
| `night_end` | night_id, duration, enemies_killed | 战斗结束 |
| `day_phase_start` | day_id | 抉择之昼开始 |
| `day_phase_end` | day_id, duration, actions_taken | 抉择之昼结束 |
| `game_end` | total_duration, nights_completed, outcome | 一局结束 |

### 6.2 可选埋点

| 事件名 | 字段 | 用途 |
|--------|------|------|
| `shop_interaction` | items_viewed, items_bought | 商店行为分析 |
| `reroll_count` | rerolls, currency_spent | 重铸频率 |
| `event_skipped` | event_id | 事件跳过率 |
