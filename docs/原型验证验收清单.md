# 原型验证验收清单

> **版本**：v3.2（对齐主文档 v0.3.4 / 单人 20 周计划）
> **日期**：2026-08-24
> **周期**：单人 20 周（W1–W20）；本版将验收范围从原型（W1–W4）扩展到**战斗核心（W5–W9）+ 成长（W10–W12）+ 商店完善/经济闭环（W13）+ 事件卡/潮汐夹击（W14）+ 局外进度（W15–W16）+ 挫败感控制（W17）+ 难度系统/HUD/结算（W18）+ 性能(350敌)/i18n（W19）+ 集成验收（W20）**——MVP 全量内容已落地
> **范围边界**：本清单验收已落地的 W1–W17 内容——昼夜循环 / 移动拾取 / 自动战斗 / 8 武器 / 9 敌人 / 6 词缀 / 3 Boss 多阶段 / 进化系统 / 精炼系统（I/II）/ 被动系统（12 被动 + 8 通用效果桶）/ 商店完善（重铸回收 80% + 休息灯塔回血）/ 事件系统（7 事件卡数据驱动 + 第 15 夜潮汐夹击天灾 + 潮汐反转事件强制两侧夹击）/ **局外进度（3 角色 + 灯塔升级树 + 星尘结算 + 版本化存档 + 首通）** / **挫败感控制（首夜保护 / 挣扎模式 / 失败保底结算 / 死亡原因可视化）**；并已机检打通「第 20 夜击杀吞噬之星 → 通关」路径。
> **不在本清单（仅人工验收项）**：350 敌同屏 60fps（Profiler 实测，机检仅验证可刷满 350 敌不崩溃）、首局完成率≥60%（真人体验统计，机检以 `w20_integration_test` 全流程可完成作为代理）、HUD 视觉排版 / 双语切词体验。难度系统 / HUD / 结算 / 性能上限 / i18n / 集成机检均已在 **v3.0（W18–W20）** 落地并机检。挫败感控制已于 **v2.8（W17）** 落地并机检；**v2.9** 为审查修复；**v3.0** 接入 W18–W20。
> **验收标准**：100 敌同屏稳定 60fps；可玩到第 8~10 夜（已达，且已打通 20 夜通关）；无阻断性 Bug。
> **机检说明**：标注「通过（机检）」的项由 `godot_project/scenes/tests/` 下专项测试覆盖（`w1_unit` / `w2w3_enemy` / `w5_weapon` / `w8_enemy_affix` / `w9_boss` / `w10_evolution` / `w11_refine` / `w12_passive` / `w13_shop` / `w14_event` / `w15w16_meta` / `w17_frustration` / `upgrade_logic` / `w18_difficulty` / `w18_hud` / `w19_i18n` / `w20_integration` 等；共 27 场景）。**全部 27 场景全 exit 0**（2026-08-18 专项修复 3 个历史遗留失败：`upgrade_logic` / `w2w3_enemy` / `w8_enemy_affix` 均为测试侧问题——开局默认武器致首次三选一走升级分支不增槽、商店随机 6 件子集不保底武器、`start_night` 首帧杂兵被计入精英分裂；逻辑本身正确，修复后三场景复跑全绿；同日 W15–W16 落地后修复单元机检跨测试存档污染回归：特性倍率改由 `MetaSystem.begin_run` 门控，单元机检（w1/w12/diag_result_ui）读到纯基线）。W17 落地后复跑 23 场景全绿；`diag_result_ui` / `game_over_halt` 两个诊断测试在开头关闭 `frustration` 复活（数据驱动 config 关闭）以验证原始「致死→结算/冻结」管线（挫败感复活仅在正式开局 `begin_run` 后生效）。标注「待验收」需人工 / Perf 试玩。
> **已知限制**：`w8`/`w9`/`w10` 专项测试含 100 敌刷怪与 Boss 战模拟，单次运行较长（数十秒级），CI 建议设超时；性能（帧率 / 崩溃 / 内存）只能人工或 Profiler 实测，机检仅验证「不崩溃 + 逻辑正确」。月食「视野」与潮汐反转「宝箱翻倍」仅有 getter（对应系统未落地），见 4.5.4 / 4.5.5。
