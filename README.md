# 潮汐守夜人 (Tidekeeper)

> 一款以「灯塔守护」为主题的肉鸽生存游戏。玩家在 20 个夜晚的潮汐侵袭中，通过武器进化、精炼与被动构筑抵御深渊生物，点亮灯塔延续光明。

**当前阶段**：可开发基准（设计文档 v0.3.4）｜单人 + agent 开发｜MVP 周期 20 周｜引擎 Godot 4.7.1 + GDScript

## 一、技术选型

### 1.1 决策依据

| 维度 | 选择 | 理由 |
|------|------|------|
| 引擎 | Godot 4.7.1 | MIT 开源无授权费；2D 原生节点；编辑器启动 <3s 热重载 |
| 语言 | GDScript（静态类型） | 语法简洁，agent 生成准确率高；静态类型提升性能 |
| 架构 | 节点系统 + 对象池 | 不引入第三方 ECS 框架，Godot 原生节点在 GDScript 中更高效 |
| 物理 | 自定义空间哈希 | Godot Physics2D 在 350+ 敌人性能差，改用自实现 |
| 渲染 | MultiMeshInstance2D | 同种敌人批量渲染，单 draw call |

**不选 Unity**：启动重、个人版有收入门槛、API 样板代码多
**不选 Phaser**：大量实体性能需手动优化、无编辑器、肉鸽生态弱
**不选 Bevy**：Rust 学习曲线陡、agent 对 Rust 游戏代码生成较弱

### 1.2 架构设计

```
Main (SceneTree)
├── World
│   ├── Player                    # 玩家节点
│   ├── EnemySpawner              # 刷怪器
│   ├── EnemyPool                 # 敌人对象池（预分配 500）
│   ├── ProjectilePool            # 投射物对象池（预分配 300）
│   ├── ParticlePool              # 粒子对象池（预分配 200）
│   ├── PickupPool                # 拾取物对象池（经验珠/潮币）
│   └── SpatialHash               # 空间哈希网格（碰撞查询）
├── UI
│   ├── HUD                       # 血条/武器槽/经验条/夜数
│   ├── DayPhaseUI                # 抉择之昼（三选一/商店/事件）
│   └── ResultUI                  # 结算/死因
├── GameState                     # 单局状态（autoload 单例）
└── SaveSystem                    # 存档系统（autoload 单例）
```

**对象池原则**：预分配 `preload` + `instantiate` 填充池；`acquire()` 激活、`release()` 失活；**禁止运行时 `instantiate`**（GC 压力）。

**数据驱动**：`config/` 为唯一数据源；武器/敌人/Boss/事件配置用 JSON；运行时启动加载到 `GameState` 单例，运行中只读。

### 1.3 性能策略

| 对象 | 策略 | 目标 |
|------|------|------|
| 同种敌人（350+） | `MultiMeshInstance2D` 批量渲染 | 单 draw call / 种类 |
| 投射物 | `MultiMeshInstance2D` 或 `CPUParticles2D` | 减少 draw call |
| 粒子 | 全局池 200 实例 + 优先级回收 | 见疑点清单 Q12 |
| 碰撞 | 自定义空间哈希（网格=敌人半径×4≈80 单位） | 不走 Physics2D |
| 敌人↔敌人 | 仅分离检测（排斥向量），不做物理 | O(n²) 仅在同网格 |
| AI 分帧 | 远程每 1 帧 / 近战每 2 帧 / 小怪每 4 帧 | 分组更新 |

**性能预算**：350~450 敌 @ 60fps（PC）｜内存 ≤512MB｜draw call ≤100

### 1.4 确定性 RNG

- 使用 Godot 内置 `RandomNumberGenerator`（基于种子，确定性）
- 全局单例 `RNG`，所有随机决策走此单例
- **整数采样优先**，避免浮点跨平台误差
- 种子管理：普通局 `randi()` 生成存入存档；每日挑战（抢先体验）服务器下发
- 同一种子 + 同一版本 = 完全一致的游戏状态

### 1.5 存档系统

```json
{
  "version": 1,
  "saves": [{
    "character": "watcher",
    "lighthouse_level": 3,
    "stardust": 1250,
    "unlocks": ["ironclad", "stargazer"],
    "settings": {"language": "zh", "volume": 0.8},
    "seed": 1234567890,
    "last_played": "2026-08-05T12:00:00Z"
  }]
}
```

- **迁移**：读取后检查 `version`，若 `< current` 按版本号逐步执行迁移函数
- **云同步冲突**：时间戳较新覆盖（默认）；两侧差 <5 分钟弹窗手动选择

### 1.6 工具链

| 工具 | 用途 |
|------|------|
| Godot 4.7.1 | 引擎 + 编辑器 |

### 1.7 agent 协作模式

**agent 擅长（充分委托）**：

| 任务 | 效率倍率 |
|------|---------|
| 脚手架代码生成 | 3-5× |
| 数据驱动配置表 | 5× |
| 重构（批量改名/提取函数） | 4× |
| Bug 定位+修复 | 2-3× |
| 测试用例生成 | 3× |

**人工不可替代（重点投入）**：玩法调优（手感/节奏/难度）、美术资源、架构决策、试玩验证。

## 三、工具脚本

所有脚本从仓库根目录运行。

### 经验表生成

```bash
python tools/generate_exp_table.py
```

- 按公式 `E(n) = floor(22 × 1.11^(n-1) + 3×(n-1))` 生成 30 级经验表
- 输出到 `config/exp_table.json`
- **红线：经验表必须由本脚本生成，禁止手改单行**

### 精炼 DPS 验证

```bash
python tools/refine_dps_simulation.py
```

- 验证 10 条精炼路径 III 级 DPS 倍率 ≤ 3.5×（封测约束）
- 锚压按「施加持续 × 覆盖率」估算，Boss 血量对齐主文档 §9.4

### 精炼风险分析

```bash
python tools/refine_risk_analysis.py
```

- 系统性检查所有精炼路径的秒杀风险
- 输出按路径分组的风险报告与开发阶段建议

## 四、配置表（数据驱动）

`config/` 目录是运行时数据源，游戏运行时只读此目录，禁止硬编码数值。

| 文件 | 说明 | 维护方式 |
|------|------|---------|
| `exp_table.json` | 30 级经验表 | 由 `tools/generate_exp_table.py` 生成（禁手改） |
| `refine_data.py` | 10 条精炼路径数据（附录 B 数据源） | 随设计文档更新，被 DPS/风险脚本共享 |
| `weapons.json` | 8 种武器 + 8 条进化路径（§9.4 + 附录 A.1） | 随设计文档更新；与 `refine_data.py` 路径 1~8 通过 `refine_path_id` 关联 |
| `enemies.json` | 9 种敌人 + 6 词缀（§5.3 + §9.4 + §8.2 公式） | 随设计文档更新；运行时按 §8.2 公式缩放 |
| `bosses.json` | 3 个 Boss（§5.5 + §9.4，第 10/15/20 夜） | 随设计文档更新；不走 §8.2 公式 |
| `events.json` | 7 张事件卡（§5.6，抉择之昼触发） | 随设计文档更新；第 15 夜排除 `tidal_reversal` |

> **JSON schema 约定**：所有配置表顶层含 `metadata`（含 `schema_version`、`doc_source`、`mvp_scope`）；实体用 `id`（snake_case）作为 key；数值字段统一 snake_case，与 GDScript 命名一致。

## 七、红线事项

1. **不得删除 MVP 范围内的任何功能**（3 角色 / 8 武器 / 8 进化 / 8 精炼 I-II / 9 敌人 / 3 Boss / 7 事件）

5. 代码需保持 **60fps 目标**（100 敌 W8 达标 / 350 敌 W19 达标）
6. 运行时只读 `config/`，禁止在代码中硬编码武器/敌人/经验数值
7. **P2 任务（埋点/双语）可砍**，但 P0/P1 不可砍
8. 锁定 Godot 4.7.1 stable 版本（4.3 LTS → 4.7.1 stable，2026-08-05 升级），避免 4.x 小版本 API 变动
